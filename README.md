# My Fresh Bag

자취생을 위한 식품 인벤토리입니다. 보유 식품과 수량을 관리하고, 사진에서 식품 후보를 읽어 등록할 수 있습니다. 화면은 HTML/CSS/JavaScript이고, 사진 분석에는 서버에서 호출하는 공식 OpenAI Node SDK를 사용합니다.

## 실행

Node.js 20 이상이 필요합니다. 최초 1회 공식 OpenAI SDK를 설치합니다.

```bash
npm install
npm start
```

브라우저에서 [http://localhost:3003](http://localhost:3003)을 여세요. 다른 포트를 사용하려면 `PORT=3004 npm start`처럼 지정할 수 있습니다.

사진 등록과 실시간 웹 검색을 사용하려면 `.env.example`을 `.env`로 복사한 뒤 `.env` 파일의 `OPENAI_API_KEY=` 뒤에 본인이 발급한 키를 입력하고 서버를 재시작하세요. 예: `cp .env.example .env`. 실제 키는 채팅이나 소스 파일에 넣지 마세요. 키는 서버에서만 읽으며 `.env`는 Git에 포함되지 않습니다. `gpt-4o-mini`는 제품 사진 식별, `gpt-6-luna`는 출처 도메인 필터를 지원하는 Responses API web_search 상품정보 검색에 사용합니다. 키가 없으면 수동 등록과 기존 인벤토리는 정상 작동합니다.

## 테스트

```bash
npm test
```

내장 Node 테스트 러너로 HTTP 제공, 경로 보호, 필수 기능 연결을 확인합니다.

## 사용 방법

- **사진으로 등록**에서 영수증 또는 제품 사진(JPG/PNG/WEBP)을 업로드하거나 모바일 카메라로 촬영합니다. 사진은 브라우저에서 축소해 서버로 보내며 API 분석 비용이 발생할 수 있습니다. 제안 결과를 확인·수정하고 체크한 항목만 등록합니다.
- **바코드 등록**에서 후면 카메라 스캔, 바코드 이미지 선택 또는 숫자 직접 입력을 사용할 수 있습니다. 브라우저의 `BarcodeDetector`가 지원되지 않으면 숫자를 직접 입력하세요. EAN/UPC 코드가 Open Food Facts에 정확히 존재할 때 이름·브랜드·용량·제품 사진·영양 정보를 미리 채웁니다. 일치 상품이 없으면 바코드를 보존해 수동 등록으로 전환합니다.
- **식품 추가**에서 이름·수량·단위·보관 장소·카테고리를 입력합니다. 식품 이름으로 보관 장소를 추천하지만 제품 라벨을 우선 확인하고 직접 변경할 수 있습니다. 소비기한, 재고 확인일, 개봉 여부와 메모는 선택 사항입니다.
- 재고 화면에는 냉장·냉동·상온 탭만 표시됩니다. 같은 상품이라도 소비기한이 다르면 별도 재고로 유지합니다. 동일 상품·같은 날짜는 새 등록 때 수량을 합칩니다.
- 인벤토리의 장소 칩 또는 검색창으로 식품을 찾습니다. 검색창은 `⌘ K` 또는 `Ctrl K`로 바로 열 수 있습니다.
- 카드의 `+` / `−`로 1단위 조절합니다. `···` 메뉴에서 원하는 양 차감, 수정, 소진 처리, 삭제를 할 수 있습니다.
- 실제 소비기한과 재고 확인일을 별도로 표시합니다. 포장에 명확하게 인쇄된 날짜만 AI가 소비기한으로 제안합니다. 불확실한 날짜는 비워두고 확인일로 바꾸지 않습니다.
- 제조일과 구매일은 각각 포장과 영수증에서 확인된 날짜만 저장합니다. 어느 쪽도 소비기한으로 계산하지 않습니다. 사진 분석 뒤 Open Food Facts에서 바코드 우선 조회를 하고, 이름 조회는 제품명·브랜드·용량이 정확히 일치할 때만 정보를 사용합니다. 찾지 못하면 별도 검색 모델의 Responses API `web_search`로 제조사, 식약처, Open Food Facts, 판매처 순으로 찾고, 결과를 코드의 신뢰 출처 도메인 목록과 대조합니다. 제품명·브랜드·버전·용량이 검증된 경우에만 정보를 채우고 출처 링크 및 조회 시각을 함께 저장합니다. 조회 결과는 브라우저와 서버 메모리에 24시간 캐시합니다.
- 제품별 영양정보는 값과 표시 기준량을 함께 보이고, 미개봉/개봉 후 보관방법을 분리합니다. 제조사 공식 출처에서 정확한 제품의 제조일 기준 소비기한 기간을 찾은 경우에만 제조일로부터 계산 날짜를 제안하며, 확인 후 저장합니다. 제품 사진은 바코드와 정확히 매칭된 Open Food Facts 이미지만 자동 적용합니다. 웹 검색 이미지는 사용권을 확인하기 전 자동 사용하지 않습니다.
- 바코드·사진 제품 카드에서 칼로리 기준량과 전체 영양정보를 펼쳐 볼 수 있습니다. 실제 포장 단위와 영양 기준 단위가 같을 때만 포장 및 현재 재고 열량을 계산합니다(예: 200g 제품과 100g 기준). 용량이 불명확하거나 g/mL가 서로 다르면 총 열량을 계산하지 않습니다. 누락된 영양소는 미확인으로 표시하며 Open Food Facts 항목은 포장 라벨과 대조하세요.
- 제한된 재고 확인일 추천은 구매일이 영수증에서 읽히고 보관이 냉장으로 확인된 생 가금류 또는 다진 육류에만 표시합니다. 추천을 확인 후 선택해야 저장되며 FoodSafety.gov 기준 출처를 함께 표시합니다. 이는 소비기한이나 안전 보증이 아닙니다.
- 개봉 후 확인일은 AI가 제품 라벨에 명시된 개봉 후 기간을 읽어 온 경우에만 계산합니다. 임의 소비기한을 생성하지 않습니다. 보관 안내는 제품 라벨과 [식품안전나라 안내](https://www.foodsafetykorea.go.kr/portal/board/boardDetail.do?bbs_no=bbs001&menu_grp=MENU_NEW01&menu_no=3120&ntctxt_no=21709)를 우선합니다.
- 데이터 백업에서 JSON 파일을 내보내거나 불러옵니다. 가져오기는 현재 인벤토리를 백업 내용으로 교체합니다.

## 저장과 개인정보

재고는 기존 키 `my-fresh-bag-inventory-v1`의 localStorage에 계속 저장되며 기존 항목은 읽을 때 새 선택 필드의 기본값만 보충합니다. 브라우저 데이터를 지우면 재고도 삭제되므로 JSON 백업을 권장합니다. 사진을 분석하면 사용자가 고른 이미지가 OpenAI API로 전송됩니다. API 키는 서버 환경 변수로만 설정합니다. Google Fonts는 선택적 외부 요청입니다.

## 정적 배포

정적 화면은 `index.html`, `styles.css`, `app.js`, `assets/`를 제공합니다. Vercel의 `api/analyze.js`와 `api/lookup.js` 함수가 서버리스 엔드포인트입니다. Vercel은 기본적으로 `AI_FEATURES_ENABLED`가 `true`가 아니면 비용 보호를 위해 사진 AI 및 OpenAI 웹 검색을 비활성화합니다. 바코드 기반 Open Food Facts 조회와 기본 재고 관리는 계속 사용할 수 있습니다. 공개 배포에는 현재 인증·공유형 호출 제한이 없으므로 `AI_FEATURES_ENABLED=true` 또는 `OPENAI_API_KEY`를 추가하지 마세요. 사진 AI를 로컬에서 사용하려면 `.env`에 키를 설정할 수 있습니다. 이후 서버 측 인증과 공유형 제한을 적용한 뒤에만 보호된 배포의 AI 활성화를 검토하세요.

`.gitignore`와 `.vercelignore`는 `.env*`(예시 파일 제외), `node_modules`, `.vercel`, 백업 폴더를 업로드에서 제외합니다. API 코드의 기존 IP별 제한은 인스턴스 메모리 기반이며 서버리스 인스턴스 간 공유되지 않습니다. 따라서 공개 배포의 AI 호출은 기본 차단합니다. Vercel 프로젝트에 AI 키를 등록하지 않아도 정적 재고 관리와 바코드 DB 조회가 작동합니다. 향후 공개 AI를 켜기 전 인증 또는 CAPTCHA, 공유형 제한과 사용량 알림을 추가해야 합니다.

## 다음 단계

AI 인식은 사용 전 확인 단계가 필수이며 식품 안전 판단을 대신하지 않습니다. 멸균/UHT처럼 제품마다 보관 조건이 다른 품목은 포장 라벨을 확인해야 합니다. 정확한 상품 사진은 사용자가 제품 사진 등록 시 제공한 사진만 저장합니다. 그 외에는 프로젝트에서 직접 만든 SVG 일러스트를 사용합니다.
